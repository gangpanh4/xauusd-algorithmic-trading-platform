# Break of Structure (BOS) Detector Specification

## Version

1.0

---

# Purpose

The Break of Structure (BOS) Detector identifies confirmed continuation events in market structure.

The detector consumes confirmed SwingPoint objects generated by the SwingDetector and emits immutable BOSEvent objects after confirming that market structure has been broken.

The detector does not generate trading signals and is independent from higher-level trading logic.

---

# Responsibilities

The BOS Detector is responsible for:

- Detecting Bullish BOS
- Detecting Bearish BOS
- Processing SwingPoint objects incrementally
- Operating as a streaming component
- Producing deterministic outputs
- Preventing duplicate BOS events

The detector is not responsible for:

- Swing Detection
- CHoCH Detection
- Liquidity Detection
- Order Block Detection
- Fair Value Gap Detection
- Trade Execution
- Risk Management
- Signal Generation

---

# Inputs

Primary Input

- Confirmed SwingPoint

Secondary Input

- Completed MarketBar

The detector must never inspect incomplete candles.

---

# Outputs

The detector emits immutable BOSEvent objects.

A BOSEvent represents a confirmed structural continuation.

The detector returns None when no BOS is confirmed.

---

# Detection Rules

A Bullish BOS requires:

- Previously confirmed structural high
- Candle closes above that structural high
- Break is confirmed on completed candle
- Event has not previously been emitted

A Bearish BOS requires:

- Previously confirmed structural low
- Candle closes below that structural low
- Break is confirmed on completed candle
- Event has not previously been emitted

---

# Confirmation Rules

The detector shall:

- Require candle-close confirmation
- Ignore wick-only breaks
- Ignore duplicate confirmations
- Ignore incomplete candles

---

# Runtime State

The detector maintains only the minimum state required.

Runtime state includes:

- Latest structural high
- Latest structural low
- Latest confirmed BOS
- Processed swing count
- Processed candle count

The detector must not maintain unnecessary historical data.

---

# Configuration

The detector configuration shall support:

- Enable / Disable detector
- Candle-close confirmation
- Duplicate prevention
- Debug logging

Future configuration may include:

- ATR validation
- Multi-timeframe confirmation

These features are not part of Version 1.

---

# Processing Pipeline

For each completed market bar:

1. Receive completed MarketBar
2. Receive newly confirmed SwingPoint (if any)
3. Update structural state
4. Evaluate Bullish BOS
5. Evaluate Bearish BOS
6. Validate event
7. Emit BOSEvent or None

---

# Validation Rules

Before emitting a BOSEvent the detector shall verify:

- Structural break is valid
- Break has not already been emitted
- Confirmation candle is closed
- Event ordering remains deterministic

---

# Public API

The detector shall expose:

- process()
- reset()
- get_last_bos()
- get_events()
- get_state()

---

# Error Handling

The detector shall gracefully handle:

- Missing SwingPoint
- Duplicate SwingPoint
- Empty state
- Reset operations

No exceptions should be raised during normal market processing.

---

# Performance Requirements

The detector shall:

- Operate in O(1) incremental time per update
- Maintain minimal memory usage
- Support continuous live execution
- Produce identical historical and live results

---

# Unit Testing Strategy

Unit tests shall verify:

## Foundation

- Initialization
- Reset
- Empty state

## Detection

- Bullish BOS
- Bearish BOS
- No BOS

## Validation

- Duplicate prevention
- Candle-close confirmation

## Edge Cases

- Equal highs
- Equal lows
- Flat markets
- Missing SwingPoints

## Streaming

- Sequential processing
- State consistency
- Long-running operation

# Integration

The BOS Detector consumes:

- SwingDetector
- SwingPoint

The BOS Detector produces:

- BOSEvent

Future consumers include:

- CHoCH Detector
- Liquidity Detector
- Order Block Detector
- Fair Value Gap Detector
- Signal Generator

---

# File Layout

Version 1 is expected to use the existing Market Structure package.

Primary implementation:

core/market_structure/bos_detector.py

Existing modules to extend if required:

- config.py
- models.py
- state.py

New modules should only be created if a clear architectural need is identified.

---

# Design Principles

The BOS Detector shall remain:

- Single responsibility
- Streaming
- Deterministic
- Non-repainting
- Modular
- Testable
- Independent
- Research-driven

The detector should prioritize correctness, maintainability, and predictable behaviour over implementation complexity.
